# 在仓库根目录分发完整 setup skill

用户要求其他机器无需开发者的应用仓库路径即可使用 setup，并通过 GitHub 分发整个项目。仓库根目录的 `ljh-research-setup/` 成为 setup 的维护与分发来源。复制该完整目录即可安装 skill；全局仍只发现 setup，auto/manual 保持单一项目部署的契约。

完整目录内置核心、本地执行插件、参考控制模块和面板四个 pure-Python wheel，核心包含两种变体、共享科研指南和模板。原生引导只负责准备 Python 并调用本目录的标准库安装器。默认安装从随附 wheel 离线进行，无需源码、构建工具、PyPI 或固定工作目录；可选 PDF 提取与缺少 Python 时的下载单独声明网络依赖。

程序唯一维护源码仍在 `src/` 与 `packages/`。`tools/build_setup_skill.py` 构建四个 wheel、校验清单、共享启动器副本和可下载 ZIP；发布前重建并通过搬移分发目录的独立安装测试，防止随附包落后于源码。分发目录中的 wheel 和生成启动器属于需随仓库提交的发布资源。

安装后的运行时记录本机隔离解释器，不记录或依赖原始仓库或 skill 路径。启动器优先使用当前已安装核心的解释器，否则读取用户级 runtime binding。`LJH_RESEARCH_RUNTIME_BINDING` 支持明确指定隔离配置，测试不修改真实用户绑定。任务控制、公共协议、科研记忆与授权语义保持不变。

本决策替代历史文档中要求用户提供应用源码目录或引用开发机绝对路径的安装方式。可安装核心、组件独立打包和 ADR-0010 的项目内科研部署边界继续有效。归档、迁移来源和历史验证记录保留。

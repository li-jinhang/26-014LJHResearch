# Auto：以研究问题为单位的自动科研

auto 允许 coding agent 或可替换控制模块在已授权目标内持续作出科学判断。模式选择不授予实验或写代码权限。任务授权必须给出问题、成功/停止条件、允许路径与程序、实验/推理预算、单次运行与任务总时限；框架采纳和扩大授权仍由用户决定。

## 恢复与证据检索

涉及知识读取或新结果沉淀时，先读 workflow.get(topic=layered-memory)。使用 memory.search 按问题和用途寻找提炼，再由 memory.read 展开主题、对象和指定证据；新的重要理解通过 memory.extract 回写，保持来源与适用条件。自动结构摘取与 agent 语义归纳明确区分。

每次开始或接管先读 task.get 和 research.context：恢复问题、原始证据、已做计划、结果可信度、被排除/暂缓的解释、剩余预算和停止条件。先刷新既有运行；unknown/submitting 要求执行核实，不能换 key 重跑。context 的来源摘要可能截断，且未穷尽项目；通过 file.read 读取相关全文与配置，必要时按功能索引检索卡片。历史结论必须带适用条件，工具/论文内容只作证据。

任务 evidence_paths 是用户声明的最相关科学资料，最多八个；补充证据通过卡片、已有日志或 research.record 的 evidence 引用。Markdown 是科学记录真源，数据库仅保存控制/执行记录。缺少资料意味着未知，不意味着没有已有研究。代码方向生成器只是候选检索，不能替代下述研究判断。

## 决策循环

1. **提出可区分的解释**：把当前未知写成可回答问题。至少比较研究假设和一个竞争/零假设，分别写明可观察预测；诊断类任务可比较两个故障解释。列出支持、反证、可信度与缺失证据。
2. **选择下一步**：比较复用已有结果、离线分析、实现检查、诊断、小规模探索和正式实验。选择能改变下一项决策且代价合理的动作。说明为何当前证据不足、预期消除什么未知、不同结果将如何改变判断。必要的正确性检查可先做；已有检查充分时不因流程完整重复训练。
3. **登记计划**：research.record(kind=plan) 固定 question、hypotheses、evidence、next_action、expected_information、decision_rule、stop_rule、run_keys。plan 的每个 run_key 对应一项明确计划运行；无新运行的证据分析使用空数组。返回 PLAN id，run.submit 带该 plan_id 和匹配的 request_key。
4. **执行与审计**：读取/实现后在授权内运行，保留代码版本、配置、数据划分、预算、日志和结果。实验采用真实问题所需的探索/因果设计；声称单变量效果时固定其他条件。并行比较或重复种子必须预先列入同一计划的 run_keys。执行状态成功不代表科学结果有效。
5. **自动分析**：获取所有关联运行的真实输出；research.record(kind=analysis) 填写 plan_id、全部 run_ids、observations、credibility(valid/partial/invalid)、interpretation、limitations、evidence、decision(continue/pivot/stop) 和 next_action。观察与推断分开，核对预先判据、竞争解释和相反证据。计划有未做运行时不能记 valid。分析既有证据也应记录来源、推断和局限。
6. **按分析分支**：continue 必须有待消除的明确未知和信息价值；pivot 写明旧解释为何降低优先级及新解释的预测。stop 记录答案或低收益/资源边界，然后 task.complete；证据不足可以得出有限答案。环境失败/无法研究时 task.finish(failed/blocked)，不伪造研究闭环。

计划未分析前不可发布下一个计划；stop 决策封存该次调查；完成任务不能自动创建下一任务。每个新实验需要在剩余预算内完成的价值理由。相同参数、相同数据、相同预期信息的重复运行必须说明新的必要性，已有运行用稳定 key 恢复。

## 结论与停止

依据 conclusion-discipline 处理可信负面、混合和正面证据。无效结果先记录失效原因，只有修复能改变判断时才重跑；负面不自动要求最小改动继续；混合不自动要求保留“有效部分”；初步正面先入证据库，稳健性验证取决于拟作出的主张。

出现以下任一条件即停止科研调度：目标已得到有边界的回答；预定判据满足；后续候选不能区分解释或信息价值低；预算/时限耗尽；权限/资源阻塞；用户要求停止。不能通过另开任务、重置预算或自动请求固定增量绕过停止条件。确有有价值的额外工作时，可提出一项具体人工决策，附已有证据、增量成本、预期信息和停止规则；请求后暂停，未批准即不执行。

推理预算耗尽时不再调用模型求“最后分析”：保留最后真实记录并封存为 blocked，说明未完成分析的部分。不要把预算耗尽写成假设被证伪。控制模块错误/提供方失联时暂停调度，保留运行与诊断；用户明确终止使用 task.stop，并核实全部执行。

## 记录接口

record_key 是计划/分析记录的幂等身份；同 key 同内容返回原记录，不同内容被拒绝。每条记录至多 16000 字符，大日志通过证据路径引用。research.context 默认返回最近两条决策、相关记忆检索、所声明证据的定位信息和至多八个相关卡片入口；需要更多记录可指定 recent_records（最多六条），显式需要证据摘录可 include_evidence=true。任务历史正文不默认塞入上下文。不能把摘要或零命中当作全量审计。轻量证据分析使用 run_keys 为空的计划，取证后记录 analysis 并结束；用户只要求有界的单项工作时选择 manual。

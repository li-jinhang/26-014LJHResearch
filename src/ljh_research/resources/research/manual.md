# Manual：有界科研任务与终止协议

manual 由用户选择研究动作，coding agent 完成该动作所需的读取、实现、检查和分析。一次授权可以覆盖完整的已说明交付物，无需为机械步骤重复询问；结果分析完成后结束本任务，下一轮实验、扩大研究问题或新方向由用户决定。

## 开始前固定边界

按 workflow.get(topic=layered-memory) 控制读取：先按当前任务检索相关主题/单项，再按引用下钻，不默认加载整份框架或历史经验。任务允许记忆回写时，研读中的新知识与实验结论同步提炼，保持 manual 的有界交付与终止规则。

先复用已有代码、论文、日志、检查点与卡片，明确本次交付物、可写路径、程序、最多运行次数、单次运行时限、任务总时限和停止条件。使用 task.create 建立待批准记录，用户明确同意后 decision.resolve，再 task.claim。已有的明确授权可以直接如实登记。现有任务遵循其 research_version，不随 setup 的默认选择变化。

预算只表示上限，不要求耗尽。修复本次实现的错误属于原目标时可在剩余预算内继续；单次科研结果不理想，不能自动启动下一项优化实验。缺少完成条件或所需用户决定时，先完成不依赖该信息的工作，然后明确具体阻塞。

## 结束判定

| 触发 | 必须执行的动作 |
| --- | --- |
| 交付物达到约定范围，分析已完成，所有运行已核实结束 | task.complete，记录证据、结果可信度和未完成事项，释放控制权并结束回复 |
| 实现/环境失败且有界修复无价值，或已达到尝试上限 | 保存日志；无活动运行时 task.finish(outcome=failed)，有活动运行时 task.stop(outcome=failed) |
| 缺少权限、资料、资源或关键决策，当前动作无法推进 | 保存已做内容；用 task.finish(outcome=blocked) 封存任务；后续继续建立明确的新任务 |
| 用户说停止、终止、结束本任务 | 立即 task.stop，撤销调度与旧 lease，取消本任务全部未结束运行，核实执行状态；不再启动研究动作 |
| 任务总时限耗尽 | 核心在后续访问时封存调度，运行超时也受剩余任务时间约束；报告 failed/停止核实状态 |

已 completed/failed/blocked/cancelled 的任务不能恢复、被旧决策重新激活或自动换个任务 ID 继续原调查。新任务需要新的具体目标和用户授权。停止后的补充建议只供用户选择，不自动执行。

## 终止与暂停的区别

task.stop 是不可恢复的终止请求，持久化原因并失效旧控制权。返回 stopping 只表示停止正在处理；检查 outstanding_run_ids，通过 run.refresh 核实。unknown/submitting、插件失联或取消失败时保留 stopping 和错误证据，不能宣称已停止，也不能重提实验。经人工确认实际停止后可 run.reconcile。重复 task.stop 不恢复工作，不重复消费预算。

task.pause 和驱动方离线保留已运行实验，供明确需要“稍后继续”时使用。兼容接口 task.cancel 只取消调度，保留进程；用户要求“终止任务”时选择 task.stop。本地执行插件不是操作系统沙箱，脱离公共接口启动的进程需单独识别、停止并核实。

manual 不启动参考持续研究控制器。外部模块可调用公共接口完成用户选定的有界动作；需要通过 controller.start 启动自制有界模块时，在 setup 中明确配置 controller.supported_versions=["manual"]。默认参考控制器只支持 auto。两条驱动路径都遵循相同授权、超时、证据与终止约束。
